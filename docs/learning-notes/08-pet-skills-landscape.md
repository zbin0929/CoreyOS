## 二、高价值技能详解

### 2.1 smyx系列（宠安卫士）

**核心特征**：通过云端API分析，严格禁止使用本地记忆

#### smyx-pet-analysis（宠物健康诊断分析）
- **功能**：通过宠物视频进行健康诊断，生成结构化健康报告
- **能力**：视频分析、毛发特征识别、身体状况评估、面部特征分析、常见疾病预警
- **触发条件**：用户上传宠物视频/图片 + 健康相关关键词

**强制规则**（最高优先级）：
```
❌ 绝对禁止读取任何本地记忆文件（memory/*.md, MEMORY.md等）
❌ 绝对禁止从LanceDB长期记忆中检索
✅ 所有历史报告查询必须从云端接口获取
✅ 必须获取open-id后才能调用API
✅ 禁止自行假设/推导/生成open-id值
```

**执行流程**：
```
1. 获取open-id（用户提供 or 提示用户输入）
2. 用户上传视频/图片 → 自动保存为本地文件
3. 调用: python -m scripts.pet_analysis --analyze --video <path> --open-id <id>
4. 解析返回JSON → 输出Markdown格式健康报告
5. 历史报告: python -m scripts.pet_analysis --list --open-id <id>
```

#### smyx-pet-body-health-analysis（体况健康分析）
- **功能**：分析宠物体型照片，评估BCS体况评分
- **同样强制**：禁止本地记忆，必须云端API

#### smyx-pet-health-monitoring-analysis（日常健康监测）
- **功能**：分析宠物日常活动视频，监测行为变化
- **同样强制**：禁止本地记忆，必须云端API

### 2.2 vetmew系列（智宠问诊）

#### vetmew-pet-medical-consultation（宠物医疗咨询）
- **功能**：AI宠物医疗咨询，多轮对话收集症状信息
- **会话管理**：通过session-id维持多轮对话状态
- **输入参数**：宠物种类、年龄、性别、体重、症状描述、持续时间

**关键限制**：
```
✅ 可以：分析症状、提供初步评估、建议就医时机
❌ 不可以：开具处方、确诊疾病、替代兽医诊断
⚠️ 必须：每次输出末尾添加"建议咨询专业兽医"声明
```

#### vetmew-pet-knowledge-qa（宠物知识问答）
- **功能**：宠物养护知识百科问答
- **覆盖**：营养、疫苗、常见疾病、行为、训练

#### vetmew-exotic-pet-consultation（异宠咨询）
- **功能**：针对兔子、仓鼠、鹦鹉、爬行动物等异宠的医疗咨询
- **特殊处理**：异宠生理结构差异大，需要物种特异性知识

### 2.3 veterinary-clinic-bundle（VetClaw宠物医院套装）

**规模**：52个AI自动化技能，专为宠物医院/诊所设计

**技能分类**：
```
前台接待类：
├─ vet-intake（新客户信息采集）
├─ vet-appointment（预约挂号）
├─ vet-phone-ai（AI电话接听，50+应答模板）
└─ vet-emergency（急诊分流，红/黄/绿三级）

病历与诊疗类：
├─ vet-lab-interpret（化验单AI解读）
└─ vet-vaccine-schedule（疫苗计划+自动提醒）

收费与财务类：
└─ vet-daily-report（每日营收报表+可视化）

营销与客户类：
└─ vet-churn-predict（流失预警，间隔>1.5倍平均=预警）
```

**工作流集成**：
```
来电/到店 → AI判断意图 → 采集信息 → 安排预约
→ 预约提醒 → 到院就诊 → 创建病历 → 开处方
→ 生成费用 → 出院指导 → 复诊提醒 → 满意度调查
```

**配置**：
- 诊所信息：`config/vet-config.yaml`
- LLM：deepseek/qwen/openai可选
- 通知：阿里云短信+微信

### 2.4 veterinary-anesthesia-plan（兽医麻醉方案）

**功能**：为兽医团队生成麻醉方案草案

**严格边界**：
```
❌ NEVER 选择最终药物/剂量/方案
❌ NEVER 发明剂量（未知=标记"Unknown — verify in formulary"）
❌ NEVER 跨物种推算（猫≠小型狗，兔≠小型猫）
❌ NEVER 未确认当天体重就计算剂量（标记PENDING DAY-OF WEIGHT）
✅ 每个输出带 DRAFT — LICENSED VETERINARIAN MUST REVIEW AND SIGN
```

**10步流程**：
```
1. 执业背景确认（角色+设施+协议库）
2. 患者信号采集（物种/品种/体重/BCS）
3. 手术信息（术式/时长/疼痛等级）
4. 病史+共病（前次麻醉事件/药物/过敏）
5. 风险标记（短头犬/视觉猎犬/MDR1品种/老年/幼年/妊娠/心脏病等）
6. 假设总结+用户确认
7. 草案输出（15节结构化方案）
8. 监护+恢复+急救药物计算
9. 设备清单
10. 自检核查
```

**15节输出结构**：
患者摘要→ASA分级→方案修改→前驱药→诱导→维持→镇痛→液体→监护→恢复→急救药物→设备清单→证据矩阵→未决问题→签署

## 三、对CoreyOS的启示

### 3.1 宠物行业Pack可行性评估

| 维度 | 评估 | 说明 |
|------|------|------|
| 市场规模 | ★★★★ | 全球宠物经济$300B+，中国$60B+ |
| 刚需度 | ★★★☆ | 健康/医疗是刚需，其余偏optional |
| 技术门槛 | ★★★★ | 需要视觉AI（视频分析）+专业知识库 |
| 合规要求 | ★★★★★ | 医疗建议必须标注"非诊断"，用药禁止推荐 |
| 付费意愿 | ★★★☆ | B端（诊所）付费意愿强，C端较弱 |

### 3.2 如果做宠物Pack的能力规划

**Phase 1（MVP）**：
- 宠物健康问答（知识库驱动）
- 疫苗接种提醒
- 基本症状分诊

**Phase 2（B端诊所）**：
- 预约管理
- 病历辅助
- 财务报表
- 客户流失预警

**Phase 3（高级）**：
- AI视觉分析（需训练模型或对接云API）
- 麻醉方案辅助
- 处方管理（法规合规要求极高）

### 3.3 关键设计模式

1. **云端强制模式**（smyx系列）：所有数据从云API获取，禁止本地缓存历史，保证数据一致性
2. **open-id网关模式**：所有API调用需用户身份标识，不允许AI自行生成
3. **医疗免责模式**：每个输出都带免责声明，区分"AI辅助"和"医疗诊断"
4. **多级分诊模式**（vet-emergency）：红/黄/绿三级，严重情况自动转人工
5. **52技能套装模式**（VetClaw）：完整工作流覆盖，从接待到回访全链路

---

> **总结**：96个宠物技能中，smyx系列（云端AI分析）和VetClaw（52技能诊所套装）最具参考价值。宠物行业Pack的核心挑战是医疗合规（必须免责声明）和视觉AI能力（视频/图片分析）。B端诊所场景比C端消费者更适合商业化。
